# AGENTS.md

Project instructions for coding agents working in this repository.

- Treat `VibingSpeech.xcodeproj` as the primary build project for this macOS app.
- Use `script/archive.sh` for release bundles so the arm64 archive, signing order, entitlements, and Hardened Runtime checks stay reproducible.
- Keep archive outputs under `build/`, which is intentionally ignored by Git.
- Change the app's Xcode Identity Version and Build through `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `VibingSpeech.xcodeproj`. Preserve the `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)` entries in `VibingSpeech/Resources/Info.plist` and the archive script checks that reject mismatched embedded bundle versions.
- The `.app` generated by `script/archive.sh` must always have Hardened Runtime enabled. Add `--options runtime` to all `codesign` calls because Launch at Login via `SMAppService.mainApp` requires Hardened Runtime at the launchd login startup stage.
- Do not use `codesign --deep` when signing archive outputs. Sign inner binaries, frameworks, and XPC bundles individually before signing the app bundle last.
- Keep the archive script Hardened Runtime regression check: fail the archive if `codesign -dvv` does not show the `runtime` flag for the generated `.app`.
- Preserve `VibingSpeech/Resources/VibingSpeech.entitlements` when signing the app. Hardened Runtime microphone capture requires `com.apple.security.device.audio-input`, so `script/archive.sh` must pass the app entitlements when it signs the top-level bundle.
- The app is Apple Silicon only; do not add Intel Mac support unless every MLX dependency and runtime path is verified for it.
- Keep AVAudioEngine tap callbacks non-main-actor isolated. In `VibingSpeech/Services/Services.swift`, create microphone tap blocks outside `@MainActor` recorder methods and hop to `MainActor` only after copying/converting audio samples.
- Keep microphone device selection bound through Core Audio in `VibingSpeech/Services/Services.swift`: enumerate input devices by `kAudioDevicePropertyDeviceUID` and set `kAudioOutputUnitProperty_CurrentDevice` on the input audio unit before reading `inputFormat` or installing the AVAudioEngine tap.
- Keep the recording overlay compact and bottom-centered. Its 150 x 33 panel geometry lives in `VibingSpeech/Views/RecordingOverlay.swift`, and the overlay should not show phase text unless that UI direction changes explicitly. Keep the processing spinner centered in the compact capsule. When Live Transcription is enabled, use the separate transcript pop-up above the compact panel; do not enlarge or replace the compact panel.
- Keep Live Transcription review-only while recording: drive the overlay from `StreamingInferenceSession`, never live-paste streaming text, and always use a separate batch transcription of the complete captured buffer for Text Processing, paste, and history after recording stops.
- Keep ASR on `mlx-audio-swift` `0.1.3` through the `MLXAudioSTT` product, with `mlx-swift` resolved to `0.31.6`. `MLXAudioSTT` contains `MLXAudioVAD` transitively, but the app must not directly import, configure, or load a VAD model. Do not reintroduce app-level VAD segmentation unless the product direction explicitly changes.
- Keep the three ASR selections in `VibingSpeech/Core/AppTypes.swift` on `mlx-community/Qwen3-ASR-0.6B-8bit`, `mlx-community/Qwen3-ASR-1.7B-4bit`, and `mlx-community/Qwen3-ASR-1.7B-8bit`. When changing these repositories, update the model metadata coverage in `VibingSpeechTests/CoreTests.swift` and the displayed download estimates together.
- Keep final Qwen3-ASR input as the complete mono 16 kHz recording in one `Qwen3ASRModel.generate` call. The library preserves one context up to its 1,200-second default boundary and independently splits longer input; do not add shorter app-level chunks or change that boundary without an explicit requirement.
- Before batch inference, model replacement, or unload, call `StreamingInferenceSession.stop()` and consume its event stream through completion. Do not use `cancel()` as a drain barrier because its detached decode task may still be winding down.
- Keep the main window content size fixed at 760 x 560 via `AppLayout` and `.windowResizability(.contentSize)`. Make overflowing detail content scroll inside the window, and preserve a working sidebar collapse/restore path.
- Keep custom sidebar rows in `VibingSpeech/Views/ContentView.swift` full-width clickable, including empty row space, by preserving the explicit row frame and `contentShape`.
- Preserve `MainWindowController` in `VibingSpeech/App/VibingSpeechApp.swift`: closing the main window should hide it, not destroy it, so the menu-bar Show Window item can restore the same window.
- Keep app-wide startup in `NSApplicationDelegate.applicationDidFinishLaunching(_:)`, not in SwiftUI view `.task` or `onAppear`: menu-bar item creation, overlay setup, permission refresh/request, ASR loading, hotkey registration, and text-processing setup must run even when the `LSUIElement` login item launches without showing a window.
- When SwiftUI views depend on nested `ObservableObject` services such as `TextProcessingService`, pass and observe the service directly instead of only reading it through `AppCoordinator`; otherwise nested `@Published` changes may not refresh loading indicators.
- Keep Appearance settings in the Other sidebar section. Drive appearance app-wide through `AppearanceService` and `NSApp.appearance` from `AppCoordinator`; do not reintroduce `.preferredColorScheme` as the source of truth in `ContentView`.
- Keep `TranscriptionRecord.originalASRText` populated for LLM-processed history records so the History tab can copy both the edited text and the original transcription separately.
- Keep Text Processing (LLM) final-only for Live Transcription. Do not run LLM processing on partial ASR or per-segment live overlay text unless the product direction explicitly changes.
- Keep Model Auto-Unload behavior explicit in `VibingSpeech/App/VibingSpeechApp.swift` and its copy in `VibingSpeech/Views/ContentView.swift`: with Text Processing enabled, standby keeps ASR and LLM loaded and idle timeout unloads both; with Text Processing disabled, standby keeps only ASR loaded and idle timeout unloads ASR.
- Keep Model Auto-Unload memory release explicit in `VibingSpeech/Services/Services.swift`: drain and release the live session, drop the ASR model reference, then clear `MLX.Memory`; also clear the cache after releasing the Text Processing model container. `mlx-audio-swift` `0.1.3` does not expose `Qwen3ASRModel.unload()`.
- When changing ASR or Text Processing model loading in `VibingSpeech/Services/Services.swift`, preserve stale-load guards and load-task cancellation/coalescing so async completions cannot overwrite newer user-selected state or disabled/unloaded state. Preserve the recording operation-generation checks in `VibingSpeech/App/VibingSpeechApp.swift` so canceling during live drain, ASR, or LLM work cannot paste or save late results.
- Keep `TextProcessingHubDownloader` honoring the tokenizer file patterns supplied by `mlx-swift-lm`; Qwen3.5 provides its required chat template as a separate `chat_template.jinja`, which `swift-transformers` merges into the tokenizer configuration after download.
- For Text Processing (LLM), use `mlx-swift-lm` with `mlx-community/Qwen3.5-4B-MLX-4bit`; keep `MLXLLM`, `MLXLMCommon`, `HuggingFace`, and `Tokenizers` linked in `VibingSpeech.xcodeproj`. Keep Qwen3.5 in non-thinking mode by passing `enable_thinking=false` through the chat template context, and preserve its recommended general Instruct sampling settings (`temperature=0.7`, `topP=0.8`, `topK=20`, `minP=0`, `presencePenalty=1.5`, `repetitionPenalty=1.0`). Do not use `/think` / `/nothink` prompt switches or app-side `<think>...</think>` stripping.
