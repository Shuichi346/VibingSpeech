# AGENTS.md

Project instructions for coding agents working in this repository.

- Treat `VibingSpeech.xcodeproj` as the primary build project for this macOS app.
- Use `script/archive.sh` for release bundles so the arm64 archive, signing order, entitlements, and Hardened Runtime checks stay reproducible.
- Keep archive outputs under `build/`, which is intentionally ignored by Git.
- Change the app's Xcode Identity Version and Build through `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `VibingSpeech.xcodeproj`. Preserve the `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)` entries in `VibingSpeech/Resources/Info.plist` and the archive script checks that reject mismatched embedded bundle versions.
- The `.app` generated by `script/archive.sh` must always have Hardened Runtime enabled. Add `--options runtime` to all `codesign` calls because Launch at Login via `SMAppService.mainApp` requires Hardened Runtime at the launchd login startup stage.
- Do not use `codesign --deep` when signing archive outputs. Sign inner binaries, frameworks, and XPC bundles individually before signing the app bundle last.
- Keep the archive script Hardened Runtime regression check: fail the archive if `codesign -dvv` does not show the `runtime` flag for the generated `.app`.
- Preserve `VibingSpeech/Resources/VibingSpeech.entitlements` when signing the app. Hardened Runtime microphone capture requires `com.apple.security.device.audio-input`, so `script/archive.sh` must pass the app entitlements when it signs the top-level bundle.
- The app is Apple Silicon only; do not add Intel Mac support unless every native inference dependency and runtime path is verified for it.
- Keep microphone capture on the input-only AUHAL in `VibingSpeech/Services/Services.swift`. AVAudioEngine can restore its default Bluetooth aggregate during initialization after an explicit microphone selection, causing a format mismatch or silent capture. Enable input and disable output before setting `kAudioOutputUnitProperty_CurrentDevice`; enumerate explicit selections by `kAudioDevicePropertyDeviceUID` and resolve System Default at each recording start without changing macOS defaults.
- Keep the AUHAL input callback outside `@MainActor`; render into its preallocated buffer and copy/convert samples before hopping to `MainActor`. Stop and dispose the audio unit before releasing callback state, then finish `MicrophoneAudioTap` and drain live delivery.
- Keep the recording overlay compact and bottom-centered. Its 150 x 33 panel geometry lives in `VibingSpeech/Views/RecordingOverlay.swift`, and the overlay should not show phase text unless that UI direction changes explicitly. Keep the processing spinner centered in the compact capsule. When Live Transcription is enabled, use the separate transcript pop-up above the compact panel; do not enlarge or replace the compact panel.
- Keep Live Transcription review-only while recording: drive the overlay from the native `GGUFStreamingTranscriber`, never paste streaming text, and always use a separate batch transcription of the complete captured buffer for Text Processing, paste, and history after recording stops.
- Keep live ASR on `handy-computer/nemotron-3.5-asr-streaming-0.6b-gguf` / `nemotron-3.5-asr-streaming-0.6b-Q8_0.gguf` through the bundled transcribe.cpp runtime. The NVIDIA official GGUF uses a different architecture and cannot be substituted directly. Do not restore Qwen MLX live models or MLX package dependencies; do not add app-level VAD.
- Keep final ASR selections on `vladers/granite-speech-5.0-470m-turboctc-GGUF` / `granite-speech-5.0-470m-turboctc-Q8_0.gguf` and `handy-computer/Qwen3-ASR-1.7B-gguf` / `Qwen3-ASR-1.7B-Q8_0.gguf`. The ggml-org Qwen GGUF is llama.cpp-specific and cannot replace the monolithic transcribe.cpp file. Keep model metadata tests and displayed download estimates aligned. Retired model selections need no compatibility mapping; unknown settings use the default model.
- Keep final ASR on the checksum-pinned transcribe.cpp `v0.4.2` XCFramework in `Packages/TranscribeRuntime`. Pass the complete mono 16 kHz recording to one native call, preserve native input-limit errors, serialize native operations, and abort/drain inference before releasing sessions or models. Keep `CTranscribe.framework` embedded, preserve `REMOVE_HEADERS_FROM_EMBEDDED_BUNDLES=NO` so unsigned Debug copies retain a valid framework signature, and include `TranscribeThirdPartyNotices.txt` in app resources.
- Keep one persistent `AVAudioConverter` in `MicrophoneAudioTap` for each recording; do not independently resample tap buffers. `MicrophoneRecorder.stop()` and `cancel()` must finish the tap and drain `LiveSampleDelivery` before final live-session stop or cancellation so captured buffers stay ordered and tail audio is not lost.
- Build final Qwen3-ASR hotword context through `ASRContextBuilder` and pass it to transcribe.cpp only when the model supports context prompts. Preserve deduplication, length bounds, whitespace normalization, and control-token delimiter neutralization. Granite CTC has no hotword/prompt support; keep this clear in the UI.
- Finalize and drain the native live stream after ordered audio delivery closes and before final batch ASR. Cancellation must abort/drain and reset without decoding the tail. Release sessions before their model, keep native work off the main actor, and select an explicit app streaming language (`auto`, `ja-JP`, `en-US`, or `zh-CN`). The v0.4.2 C API must receive nil for Auto, because the Nemotron auto prompt uses nil while the generic gate rejects the literal string `auto`.
- Keep the main window content size fixed at 760 x 560 via `AppLayout` and `.windowResizability(.contentSize)`. Make overflowing detail content scroll inside the window, and preserve a working sidebar collapse/restore path.
- Keep custom sidebar rows in `VibingSpeech/Views/ContentView.swift` full-width clickable, including empty row space, by preserving the explicit row frame and `contentShape`.
- Preserve `MainWindowController` in `VibingSpeech/App/VibingSpeechApp.swift`: closing the main window should hide it, not destroy it, so the menu-bar Show Window item can restore the same window.
- Keep app-wide startup in `NSApplicationDelegate.applicationDidFinishLaunching(_:)`, not in SwiftUI view `.task` or `onAppear`: menu-bar item creation, overlay setup, permission refresh/request, ASR loading, hotkey registration, and text-processing setup must run even when the `LSUIElement` login item launches without showing a window.
- When SwiftUI views depend on nested `ObservableObject` services such as `TextProcessingService`, pass and observe the service directly instead of only reading it through `AppCoordinator`; otherwise nested `@Published` changes may not refresh loading indicators.
- Keep Appearance settings in the Other sidebar section. Drive appearance app-wide through `AppearanceService` and `NSApp.appearance` from `AppCoordinator`; do not reintroduce `.preferredColorScheme` as the source of truth in `ContentView`.
- Keep `TranscriptionRecord.originalASRText` populated for LLM-processed history records so the History tab can copy both the edited text and the original transcription separately.
- Keep history disk access behind the `HistoryStorage` actor in `VibingSpeech/Persistence/Repositories.swift`. Await repository loading and mutations, load with the current retention setting during app startup, and preserve legacy-array migration, JSON Lines append behavior, corrupt-file preservation, and scheduled expiry for timed retention.
- Keep Text Processing (LLM) final-only for Live Transcription. Do not run LLM processing on partial ASR or per-segment live overlay text unless the product direction explicitly changes.
- Keep Model Auto-Unload behavior explicit in `VibingSpeech/App/VibingSpeechApp.swift` and its copy in `VibingSpeech/Views/ContentView.swift`: with Text Processing enabled, standby keeps ASR and LLM loaded and idle timeout unloads both; with Text Processing disabled, standby keeps only ASR loaded and idle timeout unloads ASR.
- On idle unload, abort/drain and release the native live session/model, unload final ASR, and stop the app-owned llama process. Preserve unload barriers and generation checks so an old unload cannot discard a newer model and canceled work cannot restart inference.
- When changing ASR or Text Processing model loading in `VibingSpeech/Services/Services.swift`, preserve stale-load guards and load-task cancellation/coalescing so async completions cannot overwrite newer user-selected state or disabled/unloaded state. Preserve the recording operation-generation checks in `VibingSpeech/App/VibingSpeechApp.swift` so canceling during live drain, ASR, or LLM work cannot paste or save late results.
- Keep recording startup represented by the cancellable `.starting` phase, create its operation identifier before the first suspension point, and await any pending idle-unload task before using the models. A canceled startup must not transition back to recording.
- Keep `VibingSpeechUITests` in the shared `VibingSpeech` scheme and pass `--ui-testing` when launching the app so UI smoke tests do not request permissions, load models, or depend on microphone hardware. Running the UI test target still requires a trusted macOS development-signing identity.
- For Text Processing, use `LiquidAI/LFM3-1.7B-GGUF` / `LFM3-1.7B-Q6_K.gguf` through an owned `llama serve` process. Disable thinking with `--reasoning off` and `chat_template_kwargs.enable_thinking=false`; use general sampling temperature `0.1`, top-k `50`, repeat penalty `1.1`. Do not strip reasoning tags as a substitute for non-thinking generation.
- Keep GGUF downloads in the standard `~/.cache/huggingface/hub` blob/snapshot layout with immutable commit IDs and streamed SHA-256 verification. Public models need no token UI; honor existing Hugging Face credentials without logging secrets or overwriting cached model bytes.
- Bind owned llama servers only to `127.0.0.1`, use a fresh private API key and the nondefault port candidates in `LocalLlamaServer`, and never attach to or stop an unrelated server. Stop owned processes on disable, cancellation, idle unload, and application termination. Only install llama when absent with the user-requested `curl -LsSf https://llama.app/install.sh | sh` command.
- Keep unit-test host startup isolated with the shared TestAction `--ui-testing` argument and XCTest environment detection, so tests do not load models or request hardware permissions.

- Pass native family extensions through a pointer to the complete initialized family struct, rebound to its base `transcribe_ext` header; do not take a pointer only to the nested header field when the C implementation reads trailing family fields.
- Keep native live snapshots verbatim: replace committed and tentative text from `transcribe_stream_get_text` rather than appending revisions or inserting spaces at token boundaries. Keep the trained Nemotron streaming right context at 3 (240 ms lookahead) unless product requirements change.
- Keep public package resolution out of Keychain: Xcode script invocations use `-packageAuthorizationProvider netrc`; standalone SwiftPM checks use `--disable-keychain`. Do not change the user's global GitHub credentials or installed `nemo-speech` environment.

## Documentation maintenance

- Keep setup, model/runtime, privacy, and signing guidance aligned between `README.md` and `README_ja.md`. Preserve the language switch, and maintain explicit Japanese section anchors when the table of contents uses English fragment identifiers.
- After completed implementation work, update `CHANGELOG.md`, `NOTES.md`, and `AGENTS.md` in English using the current task's evidence, including already committed or pushed work.
- Record what changed in the changelog in past tense under `Fixed`, `Added`, `Changed`, and `Removed`. Omit empty categories and routine cleanup or test-only changes unless their impact matters.
- Use `## YYYY-MM-DD` for new work, newest first, and append to existing same-day categories. Use the completion date in the user's timezone; do not guess dates or release versions. Preserve existing dated/versioned history and classify undated historical entries under `## DATE UNKNOWN` with `### Fixed`, `### Added`, `### Changed`, and `### Removed`. Do not create new `Unreleased` sections.
- Keep causes, solution rationale, behavior to preserve, known useful paths/tests, and unresolved limitations in `NOTES.md`, following its existing conventions. Keep durable, verified repository instructions in `AGENTS.md`; avoid duplicate summaries, session logs, and one-time rules.
- Read only relevant sections needed to avoid duplicates or contradictions. Reuse task evidence; inspect the smallest relevant diff or source excerpt only for missing material facts, without routinely rebuilding history.
- For a full update, consider all three root files and create missing files with minimal headings. Leave existing files unchanged when there is nothing material to add.
- Review the documentation diff and unresolved references, and run required documentation checks. Documentation-only changes do not require rerunning implementation tests solely to record the work.
